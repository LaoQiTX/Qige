# 自动备份与 Pogget 迁移计划

记录日期：2026-11-10。来自用户明确需求，两项尚未实现，不属于 beta.9 已开放功能。下一轮优先级见[开发计划](roadmap.md)。

## 自动备份与恢复（P0）

目标是用户可以恢复抽屉配置、布局、成员关系和栖格实际托管的快捷方式；现有快捷方式历史副本、退出归还机制和手动复制 `QigeData` 不能代替自动备份。

### 第一批范围

- 备份全局设置、抽屉定义、每个抽屉的配置、来源/归属记录及恢复所需元数据。
- 对栖格实际托管的快捷方式及必要历史对象保存对应文件副本；只有配置 JSON 的备份不能声称能恢复丢失文件。
- 映射目录和其他位置的引用只备份关联，不默认递归复制外部目录，也不承诺恢复外部内容。普通文件支持后再定义其完整内容备份与容量策略。
- 设置中提供自动备份开关、目标目录、频率、保留策略、最近成功/失败时间，以及立即备份和选择备份恢复入口。
- 默认可放在 `QigeData/Backups`，可改到其他磁盘；同盘默认备份用于误操作恢复，不能视为整盘故障的完整保护。

### 触发与保留

- 定时创建备份，配置变化合并触发，避免每个拖动帧创建一份快照。
- Pogget 导入、数据结构迁移及批量移除等操作前先创建可验证快照。
- 首次原型可采用完整快照，后续再评估去重；频率、份数和空间上限在实现时确定，并在界面明确显示。
- 仅在新快照成功完成并校验后轮换旧快照；保留最近可用副本，手动固定的备份不参与自动轮换。
- 排除备份目录自身、缓存、测试数据、日志和活动锁文件，避免递归备份或恢复过时锁状态。

### 一致性与恢复

- 与现有后台文件队列协调，等待文件操作结束后取得一致快照；不能边搬文件边独立复制配置。
- 使用临时目录写入，记录格式版本、来源版本、文件清单和校验值，完成后才标记为可恢复备份。
- 恢复前校验包格式、路径范围和文件完整性，预览将恢复的抽屉与内容，并先备份当前状态。
- 不覆盖桌面同名冲突文件，不删除备份范围外的用户文件；把旧布局恢复与实际内容恢复的效果说明清楚。
- 备份失败要可见、可重试；坏盘、空间不足或失败快照不能清除已有可用备份。
- 验收覆盖恢复后重新加载、文件队列繁忙、空间不足、损坏/截断包、版本不兼容、路径越界、轮换与中断恢复。

## Pogget 迁移（P1，个人迁移优先）

用户希望将自己在 Pogget 中的数据迁到栖格，可先作为一次性个人迁移处理，不要求一开始就成为通用导入功能。当前无法在未分析格式前保证可导入的字段与内容类型。

### 后续必须主动向用户索取

开始 Pogget 结构分析时，**先向用户索取以下两个目录的副本或确认可读取的位置**，不要只要求其中一个：

- `D:\.pogget\user_storage`
- `F:\pogget`

这是用户要求稍后再索取的资料。本轮仅记录，不读取、扫描或修改这两个目录；不需要现在再次询问用户。

### 分析与执行顺序

1. 以用户届时提供的数据副本为准，只读分析配置结构、版本、文件关联、分组、位置/尺寸、悬停/锁定和可识别的样式；检查是否存在数据库、压缩或额外资源依赖，不运行来源目录中的未知程序。
2. 区分真实内容、快捷方式、引用和映射路径，记录相对路径、盘符变化、缺失文件及重名冲突。不能凭同名文件推断它们是同一个入口。
3. 生成迁移清单：可直接转换、需要路径重新定位、依赖栖格尚未实现能力、无法确定的项目；明确样式和布局的转换偏差。
4. 优先用独立栖格数据目录验证转换和预览；在实际导入前备份当前栖格数据，迁移后输出结果及未处理项。
5. 保留 Pogget 原数据，不覆盖其配置，不自动删除来源。只迁移个人需要的部分即可；若后续存在复用价值，再评估通用导入界面。

快捷方式分组可优先验证；文件夹映射、普通文件及不支持的样式需要依赖相应能力。未实现类型保留在来源并列入报告，不能静默丢弃或转换成会错误搬移文件的类型。

## 交付边界

本文件只记录计划。自动备份必须有实际恢复验证后才能标为完成；Pogget 迁移须拿到上述资料并分析后再确定范围，不能把“已记录”写成“已支持导入”。个人配置、内容、原始目录副本和迁移日志不进入 Git 或 Release。
