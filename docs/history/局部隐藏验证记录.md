# 桌面图标局部隐藏 · 小型验证

日期：2026-11-07。

## 验证目的

检查能否保留真实桌面文件路径，仅从系统桌面视图隐藏已归组的单个图标，并由分区自行显示。分区拖动不再调用系统图标重排，以消除遮挡、移动不同步及挤动其他图标的问题。

本轮先检查执行局部隐藏所需的接口；前置条件不成立时不尝试桌面修改，也不以文件搬移或改变隐藏属性替代。

## 当前环境的实测结果

命令：`./build.ps1 -Task VisibilityProbe`。通过当前用户桌面的 ShellWindows → IShellBrowser → 活动桌面视图，查询相应 COM 接口。

| 查询 | 结果 | 含义 |
| --- | --- | --- |
| IFolderView2 | S_OK，0x00000000 | 当前视图支持该接口，但其公开方法不提供通用单项隐藏 |
| IShellView | S_OK，0x00000000 | 可获取桌面视图接口，不等于支持单项过滤 |
| IShellFolderView，旧接口 | E_NOINTERFACE，0x80004002 | 当前视图未暴露旧的 RemoveObject 所属接口 |

结果保存于 `TestData/DesktopVisibility/capabilities.json`。探测程序不移动文件、不改变文件属性、不移动或隐藏图标。当前无待恢复的旧布局记录。

**结论：通过上述公开接口直接移除指定桌面显示项的候选路线，前置验证未通过。** 未执行两图标隐藏、刷新后保持隐藏、Explorer 重启和异常退出恢复。不能把接口查询当作这些行为通过，也不能据此声称所有技术路线都不可行。

## 文档依据

- [IFolderView2](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ifolderview2)：列出的公开方法包括选择、位置、视图模式和分组等，不提供通用的单项可见性开关。
- [IShellFolderView](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nn-shlobj_core-ishellfolderview)：微软注明自 Windows 7 起不再可用。
- [RemoveObject](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-ishellfolderview-removeobject)：旧方法移除的项也可能随时被数据源重新加入，因此即使某台系统暴露接口，也不能据此保证更新和刷新后的稳定隐藏。

## Fences 的事实边界

[Fences 官方产品页](https://www.stardock.com/products/fences/)把普通 Fence groups 描述为桌面内容的分组区域，把 Folder Portals 描述为将文件夹映射到桌面。两者应分别理解，不能把每个普通分区等同于实际文件夹。

这些资料没有说明其当前内部如何协调系统图标、绘制、隐藏和同步，也没有足够证据确认它使用临时搬移文件、某个特定 COM 接口或某种注入方式。本项目不将推测当成 Fences 的实现事实。

## 下一步架构选择

1. 保留原文件路径，改为自行绘制整层桌面图标，包括分区外图标；系统图标视图整体隐藏。这避开单项隐藏难点，但要承担选择、拖放、系统菜单、键盘操作及异常退出恢复等更大范围的工作。尚未验证。
2. 实际收纳到项目目录，退出时恢复。无需单项隐藏，但要处理跨盘迁移、占用、重名冲突、异常恢复和更新器在原桌面重新生成快捷方式。与用户优先保留原路径的偏好有取舍，不能默认切换。
3. Explorer 更深层扩展需要独立研究与兼容验证。本轮没有实施此类修改，也没有验证其必要性或可靠性。

低饱和深色半透明、细标题栏、原色图标的视觉方向已接受；本轮仅做架构前置验证，没有将绿色测试框包装成正式版本。
