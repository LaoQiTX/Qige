# 稳定性验收

beta.9 收尾桌面生命周期与诊断，随后再进入文件夹映射。以下保留实现和本地候选包的验收记录，人工场景结果仍按实际完成情况填写。

## 本轮修改

- 连续环境通知按 300 ms 安静窗口合并，最迟在本轮通知开始两秒时允许恢复。实际执行还取决于 UI 调度；重复通知不重置失败后的 1、2、4、8、16、30 秒退避。
- 环境计时器检查恢复策略，不再因每个通知重启计时。拖动中的抽屉仍等待交互结束后恢复。
- 桌面连接日志移到后台文件队列，合并慢写期间的快照；写入失败后继续恢复桌面，并允许后续写入重试。
- 性能明细保持 240 项上限，同时保留整次运行的累计统计。不会随运行时间增加而无限保存明细。

## 全天资源记录

从托盘进入“运行与恢复”，打开日志目录。建议在启动后 10 分钟、1 小时、4 小时、8 小时保存 `performance-current.json` 和 `desktop-lifetime.json`，分别放入本次验收记录目录；记录采样时是否正在交互、面板是否可见。

重点读取性能日志中的 `Session`：

| 字段 | 用途 |
| --- | --- |
| `StartedAt` / `UptimeSeconds` | 核实是否同一运行会话、实际持续多久 |
| `TotalSamples` / `ObservedSeconds` | 核实累计采样数与最近采样覆盖时间 |
| `AverageCpuPercent` | 截至最近一次采样的时间加权平均 CPU，按逻辑处理器数归一 |
| `InitialWorkingSetMB` / `InitialPrivateMB` | 本次记录器启动时的内存基线 |
| `PeakWorkingSetMB` / `PeakPrivateMB` | 累计采样观测到的峰值，非操作系统高频峰值 |
| `WorkingSetChangeMB` / `PrivateMemoryChangeMB` | 最近采样相对初始基线的变化，包含正常缓存与界面加载 |

比较 10 分钟预热后的同类空闲场景，避免将一次图标缓存加载直接当成泄漏。明细中的 CPU 与 UI 延迟包含系统调度、睡眠和同期操作的影响。连接日志只覆盖最新状态，遇到异常及时另存。

每个场景按下列格式记录，不能用自动检查结果代填人工结论：
