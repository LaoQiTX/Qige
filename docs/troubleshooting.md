# 问题排查

从底栏“设置 → 运行与恢复”查看桌面连接、文件操作和待处理项目。也可从托盘直接打开统一设置。

## 找不到抽屉

1. 选择“定位全部抽屉”，或选中一个抽屉后“桌面定位”。
2. 如果连接数量不完整，点击“重新连接桌面”，等待自动重试。
3. 检查是否刚更换显示器、缩放、唤醒或重启 Explorer。抽屉会尝试重新挂接，临时回收到可见工作区。

程序不会为修复显示而重排其他桌面图标。仍不可见时记录显示器、缩放、复现步骤及 `QigeData/logs` 中的连接日志。

## 拖入后没有收纳

整理抽屉只收纳个人桌面根目录的项目。其他位置可使用外部引用或文件夹映射。样例使用独立目录。

抽屉尚未连接、正在处理文件或移除时，会暂时拒绝新的收纳操作。等待当前任务完成后再试。文件被占用、权限不足或路径经过符号链接/目录联接时也可能停止收纳。

桌面显示的图标也可能来自公共桌面（通常为 `C:\Users\Public\Desktop`）。从 `1.1.0-beta.1-diag.2` 起，DeskBox 等公共桌面项目直接拖入整理抽屉会自动添加为引用，与右键“引用外部文件…”一致，公共桌面原件和图标保留。需要实际移走桌面图标时，先自行将原件移到个人桌面后再收纳。混合拖入时，个人桌面项目收纳，公共桌面项目引用。

遇到“拖不进去，但右键添加成功”时，使用同一个文件依次尝试拖入和右键添加，然后在“设置 → 运行与恢复 → 打开日志目录”获取 `input-current.jsonl` 和存在时的 `input-previous.jsonl`。日志默认启用，记录软件版本、是否以管理员权限运行、拖放注册结果、OLE 文件格式、路径、按键与拖放效果、拒绝原因、后台收纳结果和异常堆栈。每次拖入的 `OperationId` 可关联接收与后台结果；`input.route` 区分收纳与引用，`ole.receive-returned` 的 `Queued` 表示接收成功，实际结果看 `input.completed`。

若复现期间完全没有 `ole.enter`，请连同 `ole.register` 和 `session.start` 一起反馈，以检查拖放事件是否到达窗口，以及进程权限和桌面挂接情况。日志在本机后台写入，单个文件上限 2 MiB，保留当前及上一份；大量事件时队列保留最近记录，`Sequence` 跳号可能表示丢弃。日志包含本机路径，分享前请脱敏。

## 软件更新后出现重复入口

栖格检查已分组入口的原桌面路径，并核对目标、参数和工作目录。可靠匹配时同步新快捷方式并保留先前副本；不同目标或无法确认的文件会保留在两处，交由用户处理。

它不会仅凭文件名合并所有快捷方式，也不会自动归类尚未加入任何抽屉的入口。

## 归还冲突，或无法退出

“运行与恢复”显示桌面与收纳两处完整路径：

1. 打开两处位置，检查内容。
2. 将桌面上需要保留的同名文件改名或移到其他位置；不要直接覆盖收纳文件。
3. 点击“检查并重试”。
4. 处理完成后，再选择“退出并归还全部”。

“另存收纳副本”会在 `QigeData/recovery/exports` 中保存经 SHA256 校验的副本，保留原件和分组。

若软件已卸载，桌面与收纳文件都已被外部删除，beta.12 起不再因此阻止退出。确认不再需要后，直接在工作台内容列表点击该项的“移除失效记录”，或在“设置 → 运行与恢复”使用同名操作并确认，即可从抽屉和待处理列表中清除；历史元数据与已有副本保留，不删除文件。若文件重新出现、存在待处理副本或目录不可访问，会拒绝清理。程序不能恢复已被外部删除且没有备份的文件内容。

旧版若因上述缺失记录无法退出，可在确认文件操作已结束后，通过任务管理器结束 Qige，再安装新版。保留原 `QigeData`，新版会继续读取恢复记录；不要为解除退出阻塞删除整个数据目录。

## 异常退出后入口不在桌面

从原软件目录重新启动，让程序读取原 `QigeData`，再执行全部归还。不要删除数据目录、手动合并多套配置，或在仍收纳内容时清理软件文件。

关机、强制结束和断电不保证完成退出归还；中断记录用于下次继续恢复。

## 安装或启动提示目录不可写

选择当前用户可写的目录。运行数据默认在 EXE 旁，程序不会自动改存 AppData。不需要通过管理员运行来解决日常写入问题。

安装器提示程序仍运行时，先从托盘选择退出并归还。卸载保留 `QigeData`；迁移电脑或磁盘时请保留这份数据。

## 查看性能与日志

性能每 15 秒采样，最多保留 240 个样本，写入 `QigeData/logs/performance-current.json`，不上传。图标缓存上限为 256 项。

CPU 按整机逻辑处理器数归一；首次就绪计时从管理窗口构造开始。调度延迟不是帧率，短时采样也不能证明长期稳定。详细口径见[验证说明](validation.md)。

## 提交反馈

在 [Issues](https://github.com/LaoQiTX/Qige/issues) 提供软件版本、Windows 版本、显示器分辨率/缩放、复现步骤和期望结果。涉及 Wallpaper Engine 或其他桌面整理工具时，一并说明。

日志可能包含本机路径，分享前请脱敏；不要上传个人快捷方式或整个 `QigeData`。
